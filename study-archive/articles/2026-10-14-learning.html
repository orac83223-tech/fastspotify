SIEVE와 캐시 교체: 매번 최근 사용 순서를 고치지 않아도 되는 이유

LRU의 재사용 거리에서 출발해 SIEVE의 방문 비트와 이동하는 hand를 손으로 실행한다. 이기는 예제와 지는 반례, 상각 O(1) 증명, 미스 비용의 손익분기 계산을 통해 적중률과 관리 비용을 함께 최적화하는 법을 배운다.

03

중심 원자료와 선수개념

중심 원자료는 Yazhuo Zhang, Juncheng Yang, Yao Yue, Ymir Vigfusson, K. V. Rashmi의 「SIEVE is Simpler than LRU: an Efficient Turn-Key Eviction Algorithm for Web Caches」이다. NSDI 2024, 2024년 4월 16~18일 학회 논문이며, 2026년 10월 14일 한국시간에 공식 원문을 열어 §3의 알고리즘, §4의 평가, §7.2의 한계를 확인했다. 중심 논문 PDF

필요한 선수개념은 해시 테이블, 양방향 연결 리스트, 확률의 기댓값, 빅오 표기다. 해시 테이블은 키에서 객체 위치를 찾고, 연결 리스트는 객체 사이의 순서를 관리한다. 기댓값은 각 경우의 비용에 발생확률을 곱해 더한 값이다. 상각 분석은 어떤 한 번의 연산이 오래 걸리더라도 연속된 전체 연산의 총비용을 제한하는 방법으로, 확률적 평균과는 구별한다.

이 글에서 캐시는 동일한 크기의 객체를 최대 C개 저장하는 소프트웨어 캐시다. 요청은 하나씩 처리하고, 만료·삭제·실패·동시성은 먼저 제외한다. 마지막 부분에서 이 가정을 다시 풀겠다. 실제 바이트 용량 기반 캐시에서는 큰 객체 하나를 넣기 위해 여러 객체를 내보낼 수 있으므로 손계산의 “미스 한 번에 교체 한 번”이 그대로 성립하지 않는다.

04

1. 캐시는 답을 기억하지만 교체 정책은 미래를 추측한다

캐시 적중, 즉 hit는 요청한 객체가 이미 저장돼 있는 경우이고, miss는 그렇지 않은 경우다. 요청 수를 R, 적중 수를 H라 하면 적중률은 h = H/R, 미스율은 m = 1 − h다. 객체 자체를 올바르게 돌려주는 문제와, 나중에도 유용할 객체를 골라 남기는 문제는 분리돼 있다.

용량이 충분하면 모든 객체를 보관할 수 있다. 그러나 서로 다른 객체 수가 C보다 많아지면, 새로운 객체를 넣는 순간 무엇인가를 버려야 한다. 앞으로 가장 늦게 다시 쓰일 객체를 알 수 있다면 훌륭한 결정을 내릴 수 있겠지만, 온라인 서비스는 아직 도착하지 않은 요청을 모른다. 과거 사용 흔적을 미래의 유용성에 대한 대리 정보로 쓴다.

FIFO는 들어온 순서, LRU는 마지막으로 사용된 순서를 기준으로 내보낼 대상을 고른다. LRU의 전제는 최근에 쓰인 객체가 가까운 미래에도 쓰일 가능성이 있다는 시간적 지역성이다. 정확한 최근성 관리에도 비용이 있어 CLOCK 같은 근사 정책이 등장한다. 기본 배경은 OSTEP 22장의 교체 정책과 근사 LRU 설명에서 확인할 수 있다. OSTEP 22장

여기서 근사는 반드시 데이터의 정답을 흐린다는 뜻이 아니다. 어제 계산한 값을 오늘의 값처럼 돌려주는 것은 정합성 오류다. 재사용될 객체를 잘못 내보냈다가 원본에서 다시 가져오는 것은 성능 손실이다. 어떤 근사를 허용하는지 먼저 정해야 한다. 교체 정책의 오판을 데이터 정확성의 오판과 같은 것으로 취급해서는 안 된다.

05

2. LRU를 정확히 이해하는 도구는 재사용 거리다

용량 C의 LRU가 있고, 모든 미스에서 해당 객체를 캐시에 넣는다고 하자. 한 객체 x의 연속된 두 요청 사이에 등장한 서로 다른 다른 객체의 수를 d(x), 즉 재사용 거리라고 정의한다. 같은 객체가 중간에 여러 번 등장해도 한 번만 센다. 처음 보는 객체는 이전 요청이 없으므로 별도로 cold miss로 처리한다.

이 조건에서 LRU 적중 조건은 d(x) < C다. 직전 x 요청이 끝나면 x는 가장 최근 위치에 있다. 이후 서로 다른 다른 객체가 하나 등장할 때마다 x보다 최근인 객체가 하나 늘어난다. 그 수가 C가 되는 순간 x는 용량 밖으로 밀린다. 따라서 d(x)가 C − 1 이하일 때만 다시 요청되는 x가 남아 있다. 이는 주어진 정의와 LRU 규칙에서 직접 얻는 성질이다.

예를 들어 요청 A → B → B → C → A에서 두 A 사이의 전체 요청은 세 번이지만 서로 다른 객체는 B와 C 두 개다. 따라서 d(A) = 2다. 용량 C = 3이면 마지막 A는 적중하고, C = 2이면 미스다. 시간상 1밀리초가 지났는지 1시간이 지났는지는 이 모형의 판단 기준이 아니다.

이 관점은 인기와 최근성을 구별해 준다. 하루 동안 천 번 요청된 객체라도 최근 수천 종류의 객체가 그 사이에 끼었다면 작은 LRU에서는 사라질 수 있다. 반대로 전체 빈도가 낮아도 짧은 간격으로 두 번 요청되면 적중할 수 있다. “인기 있는 객체를 저장한다”는 설명만으로는 정책을 정확히 예측할 수 없는 이유다.

모든 요청을 같은 크기로 취급하고 만료나 선별 입장이 없을 때의 성질임을 기억하자. 바이트 크기가 다르거나 일부 미스를 저장하지 않는 정책에서는 서로 다른 객체 수만으로 적중 여부를 판단할 수 없다. 뒤에서 SIEVE의 흔적을 볼 때에도 LRU의 재사용 거리 공식을 무심코 가져오면 안 된다.

06

3. 데이터를 읽었는데 관리 정보에는 쓰기가 발생한다

전형적인 해시 테이블과 양방향 리스트 기반 LRU를 생각하자. 키를 찾은 뒤 그 객체를 최근 사용 위치로 옮기려면 기존 이웃의 연결을 바꾸고 리스트 앞쪽에 다시 연결해야 한다. 이미 맨 앞에 있는 경우를 제외하면 데이터 조회가 리스트 갱신을 동반한다. 자료구조 관점에서는 상수 개의 포인터 작업이므로 O(1)이지만, 여러 CPU가 같은 순서를 동시에 고치려 하면 상황이 달라진다.

빅오는 용량 C가 커질 때 연산 수가 어떻게 늘어나는지 설명한다. 같은 메모리 위치의 쓰기 권한을 CPU 사이에서 넘기는 비용, 잠금 대기, 메모리 배치에 따른 차이까지 모두 설명하지는 않는다. “둘 다 O(1)이니 성능도 비슷하다”는 판단은 잘못될 수 있다. 특히 조회가 대부분인 서비스에서는 아주 짧은 관리 작업도 요청 수만큼 반복된다.

여기서 세 선택이 생긴다. 정확한 전역 순서를 계속 유지하거나, 캐시를 여러 조각으로 나눠 조각마다 순서를 유지하거나, 순서 정보를 덜 정밀하게 기록한다. 조각내기는 경합을 줄이지만 여유 공간을 모든 객체가 자유롭게 나눠 쓰지 못하게 할 수 있다. 갱신을 일괄 처리하면 비용이 줄지만 정책이 보는 최근성은 실제 요청 순서보다 뒤처질 수 있다.

따라서 비교 실험에서 한쪽은 엄밀한 전역 LRU이고 다른 쪽은 분할된 근사 정책이라면, 결과에는 교체 규칙 외에 동기화와 용량 분할 효과도 섞인다. 어떤 데이터를 지켰는지와 어떤 관리 작업을 생략했는지를 따로 봐야 한다. 오늘의 SIEVE는 특히 히트마다 객체를 이동시키는 작업이 꼭 필요한지 묻는다.

07

4. SIEVE의 상태와 규칙을 정확히 정하자

SIEVE는 삽입 순서의 리스트, 다음 후보를 가리키는 hand, 객체별 visited 비트를 둔다. 새 객체는 최신 삽입 끝에 비트 0으로 들어간다. 적중하면 비트만 1로 만든다. 공간이 필요하면 hand부터 오래된 쪽에서 새로운 쪽으로 검사한다. 비트 1이면 0으로 바꾸고 제자리에 남기며, 비트 0이면 내보낸다. hand는 내보낸 객체 다음으로 이동한다. 끝을 지나면 가장 오래된 남은 객체부터 다시 돈다. 알고리즘 1

이하 표기에서 리스트는 왼쪽이 오래된 삽입, 오른쪽이 새로운 삽입이다. A₀는 A의 비트가 0, A₁은 1이라는 뜻이다. 처음 hand는 비어 있으며 첫 교체를 시작할 때 왼쪽 끝을 본다. 교체 후 다음 객체가 없으면 hand를 비워 두고, 다음 교체가 시작될 때 그때의 왼쪽 끝으로 돌아간다.

직접 따라가면 가장 헷갈리는 점이 드러난다. 객체를 처음 요청해 가져온 것도 사용인데 왜 처음 비트는 0일까? 여기서 비트는 “이 객체를 세상에서 사용한 적이 있나?”를 기록하지 않는다. 새로 들여온 뒤 재사용이 있었는지, 또는 마지막 비트 초기화 뒤 적중이 있었는지를 기록한다. 삽입 자체로 보호 점수를 주면 처음 한 번만 쓰이고 사라질 객체까지 모두 한 차례 더 보호하게 된다.

또한 비트 0은 즉시 삭제하라는 명령이 아니다. hand가 그 객체를 실제 후보로 만났을 때의 판단 기준이다. 공간이 충분하거나 hand가 다른 구간에 있으면 비트 0인 객체도 남는다. 상태값과 그 상태를 읽는 시점을 함께 알아야 알고리즘이 결정된다.

08

5. 손계산 하나로 hand의 효과를 확인한다

아래는 이 글을 위해 만든 예제다. 빈 캐시, 용량 C = 3, 요청열 A → B → C → A → D → E → F → A를 사용한다. 최초 세 번의 적재도 미스로 센다. 같은 크기의 객체를 요청마다 하나씩 처리하며, TTL이나 입장 필터는 없다.

1~3번째 요청 A, B, C: 모두 미스다. 캐시는 A₀ → B₀ → C₀이고 아직 교체가 없어 hand는 비어 있다.

4번째 요청 A: 적중한다. 순서는 그대로 A₁ → B₀ → C₀다. A를 오른쪽으로 옮기지 않는다.

5번째 요청 D: 꽉 찼으므로 A부터 검사한다. A₁을 A₀으로 바꾸고 통과한다. 이어 B₀을 내보내고 D₀을 오른쪽에 넣는다. 결과는 A₀ → C₀ → D₀, hand = C다. 이 요청에서 후보를 두 번 검사했다.

6번째 요청 E: hand가 가리키는 C₀을 내보낸다. 결과는 A₀ → D₀ → E₀, hand = D다. 7번째 요청 F에서도 D₀을 내보낸다. 결과는 A₀ → E₀ → F₀, hand = E다. A₀이 왼쪽 끝에 남아 있다고 해서 매번 다시 검사하지 않는다.

8번째 요청 A: A는 아직 있으므로 적중한다. 최종 상태는 A₁ → E₀ → F₀다. 적중 2번, 미스 6번이므로 h = 2/8 = 25%, m = 6/8 = 75%다. 전체 교체 후보 검사는 2 + 1 + 1 = 4번이다.

같은 요청열에서 LRU는 다르게 움직인다. 4번째 A 직후 오래된 사용부터 나열하면 B → C → A다. 이후 D와 E를 넣으면 A → D → E가 되고, F가 들어올 때 A가 가장 오래돼 나간다. 마지막 A는 미스다. 적중 1번, 미스 7번이므로 h = 12.5%, m = 87.5%다. 마지막 A의 재사용 거리는 D, E, F의 세 종류, 즉 3이므로 앞 절의 조건으로도 확인된다.

이 예제의 핵심은 A가 최근성 순위에서 계속 올라갔다는 것이 아니다. hand가 이미 A를 지나 새로운 객체들 쪽으로 이동했고, 그동안 재사용되지 않은 D가 A보다 먼저 나갔다는 것이다. 시간마다 모든 객체의 정확한 순위를 유지하지 않아도 유용한 구분을 만들 수 있다. 다만 여덟 번의 요청에서 이겼다는 사실은 어떤 요청열에서나 이긴다는 증명이 아니다.

09

6. 한 비트는 무엇을 잊고 무엇을 남기는가

한 비트가 1이면 그 기간에 한 번 적중했는지 백 번 적중했는지 구분할 수 없다. A에 대한 요청이 잠깐 폭발적으로 몰려도 이미 비트가 1이면 보호 신호가 계속 커지지 않는다. 그 대신 필요한 기록량과 갱신 작업을 작게 유지한다. 이는 정확한 횟수를 기록하지 않는 정보 압축이라고 볼 수 있다.

정보를 잃는 것이 유리할 수 있는 이유는 목적 때문이다. 현재 질문이 “A가 정확히 몇 번 요청됐나?”라면 한 비트는 불충분하다. 현재 질문이 “이번 후보 검사에서 A에게 한 번 더 기회를 줄 증거가 있나?”라면 이진 신호로도 결정을 내릴 수 있다. 관측 정보를 정교하게 만드는 것과 의사결정을 개선하는 것은 동일한 문제가 아니다.

비트가 나타내는 시간창도 고정된 1초나 100번의 요청이 아니다. hand가 객체에 도착해 비트를 지우는 시점이 창의 경계다. 미스와 교체가 드물면 오래된 재사용 흔적이 오래 남을 수 있고, 교체가 잦아지면 검사가 빨라질 수 있다. 따라서 서로 다른 부하에서 같은 비트 1이 같은 “최근 몇 초”를 뜻하지 않는다.

여기서 과도한 해석을 피하자. 한 비트는 미래 인기도의 충분통계량이라고 증명된 것이 아니다. 통계적 충분성은 원래 분포와 모수에 대한 별도 조건을 요구한다. 이 글에서의 해석은 주어진 교체 결정을 위해 더 싼 관측 신호를 쓰는 설계라는 뜻이다. 보호를 단순하게 만드는 대가로 새롭게 뜨는 객체를 놓칠 가능성도 남는다.

10

7. 한 번에 오래 걸려도 총비용은 작을 수 있다

이제 확률을 쓰지 않는 상각 분석을 해보자. 앞에서 정한 단일 스레드 모형, 처음 비어 있는 캐시, 고정 크기 객체를 그대로 사용한다. R은 총요청 수, H는 적중 수, E는 실제로 내보낸 객체 수다. V는 교체 과정에서 비트를 확인한 후보의 총개수로 정의한다. 해시 조회나 연결 변경 횟수는 별도로 상수 비용으로 센다.

후보 검사에는 두 종류만 있다. 0을 만나 객체를 내보내는 검사와, 1을 만나 0으로 바꾸고 통과하는 검사다. 전자는 교체마다 한 번이므로 총 E번이다. 후자 한 번에는 그 전에 해당 비트를 0에서 1로 만든 적중이 반드시 하나 필요하다. 같은 0→1 변화로 두 번의 초기화 비용을 지불할 수는 없다.

비트를 실제로 0에서 1로 바꾼 적중 수를 H₀₁, 끝날 때 남은 비트 1의 수를 Φ라고 하자. 삽입은 0으로 시작하고, 이 모형에서는 1인 객체를 바로 내보내지 않으므로 초기화 횟수는 H₀₁ − Φ다. 따라서 V = E + H₀₁ − Φ ≤ E + H ≤ R이다. 마지막 부등식은 E가 미스 수보다 클 수 없기 때문이다.

손계산 예제에서는 E = 3, H₀₁ = 2, Φ = 1이다. 따라서 V = 3 + 2 − 1 = 4로, 실제 센 네 번과 일치한다. 각 적중이 나중의 검사 비용을 미리 지불하는 쿠폰 한 장을 만든다고 생각하면 쉽다. 이미 1인 비트에 다시 적중해도 쿠폰이 여러 장 쌓이지 않는다.

이로부터 요청열 전체에 대한 후보 검사 비용은 O(R), 요청당 상각 비용은 O(1)이다. 기대 O(1)의 해시 조회와 상수 시간 연결 변경을 더하면 전체 정책 비용도 같은 차수로 분석할 수 있다. 해시 충돌의 최악 경우, 메모리 할당, 객체 가져오기 비용까지 무조건 상수라는 말은 아니다.

반면 개별 미스가 반드시 O(1)인 것은 아니다. C개 객체의 비트가 모두 1이면 한 번씩 지운 뒤 처음 위치로 돌아와 0인 하나를 내보낸다. 후보 검사가 C + 1번 필요하다. 평균적인 총작업량을 제한하는 성질과, 특정 요청의 최대 지연을 제한하는 성질은 다르다. 동시 적중이 검사 도중 비트를 다시 세우는 구현에는 이 단일 스레드의 C + 1 상한을 그대로 적용할 수도 없다.

11

8. 반례를 만들면 정책의 취향이 보인다

이번에는 같은 C = 3에서 요청열 A → B → C → A → C → D → B → D를 보자. 역시 이 글에서 만든 반례이며 두 정책 모두 빈 캐시에서 시작한다. 첫 다섯 요청이 끝나면 두 정책은 A와 C에서 각각 한 번씩, 총 두 번 적중했다.

SIEVE 상태는 A₁ → B₀ → C₁이다. D가 오면 A의 비트를 지우고 B를 내보내 A₀ → C₁ → D₀, hand = C가 된다. 다음 B 요청에서는 C의 비트를 지우고 D₀을 내보낸다. 따라서 마지막 D는 다시 미스다. SIEVE는 적중 2번, 미스 6번이다.

LRU는 첫 다섯 요청 뒤 B → A → C다. D가 오면 B를 내보내 A → C → D가 되고, B가 다시 오면 A를 내보내 C → D → B가 된다. 따라서 마지막 D는 적중한다. LRU는 적중 3번, 미스 5번이다. 이 짧은 요청열에서는 SIEVE가 미스 하나를 더 만든다.

새 객체를 빨리 시험하고 내보내는 성향은 잠깐 머문 뒤 다시 오는 객체를 너무 일찍 버릴 수 있다. 앞 예제에서는 재사용되지 않을 D를 빨리 버린 일이 도움이 됐지만, 이번에는 D가 곧 돌아와 손해가 된다. “재사용되지 않은 객체를 빨리 내보낸다”는 같은 규칙이 두 상황에서 반대 결과를 낸다.

원논문도 SIEVE가 scan-resistant하지 않음을 명시한다. 따라서 웹 캐시에서의 결과를 반복 스캔이 잦은 블록 캐시에 그대로 일반화하면 안 된다. 한계 논의 §7.2

스캔 저항성은 많은 일회성 접근이 들어왔을 때 기존의 유용한 작업 집합을 얼마나 잘 보존하는지와 관련된다. 앞 절에서 A가 잠깐 남았다는 사실만으로 그 성질이 보장되지는 않는다. 좋은 교육용 예제는 원리를 드러내지만, 반례를 지워 주지는 않는다.

9. 적중률이 조금 나빠져도 전체 비용은 좋아질 수 있다

두 정책의 서비스 시간을 비교하는 작은 모형을 만들자. c는 요청당 평균 캐시 처리시간, m은 미스 확률, B는 미스 한 번에서 추가로 드는 원본 가져오기 시간이다. 줄 서서 기다리는 시간과 요청 간 상호작용을 제외하고 B가 두 정책에서 같다고 두면, 평균 서비스 시간은 T = c + mB다. c에는 적중과 미스 양쪽의 캐시 내부 관리비를 평균해 포함한다.

정책 A와 B를 구별하기 위해 아래에서는 새 정책을 N, 기존 정책을 L로 쓰자. 새 정책이 Δc = c_L − c_N만큼 관리비를 줄이지만 미스율을 Δm = m_N − m_L만큼 높인다면 T_N − T_L = −Δc + Δm × B다. Δm > 0일 때 새 정책이 유리한 조건은 B < Δc/Δm다. 단위는 시간 ÷ 무차원 확률이므로 다시 시간이다.

교육용 수치를 넣자. 기존 정책은 c_L = 0.4μs, m_L = 0.050이고, 새 정책은 c_N = 0.1μs, m_N = 0.055라고 하자. 이 수치는 SIEVE나 특정 제품의 실측값이 아니다. Δc = 0.3μs, Δm = 0.005이므로 손익분기점은 B = 0.3/0.005 = 60μs다.

원본 가져오기 시간이 B = 20μs이면 기존 정책의 T_L = 0.4 + 0.050 × 20 = 1.4μs이고, 새 정책의 T_N = 0.1 + 0.055 × 20 = 1.2μs다. 미스가 조금 늘어도 관리비 절감이 더 크다. 반대로 B = 500μs이면 T_L = 25.4μs, T_N = 27.6μs라서 기존 정책이 유리하다.

이 계산이 주는 교훈은 적중률이 중요하지 않다는 것이 아니다. 미스 한 번의 가격과 관리 작업의 가격을 같은 단위로 환산해야 한다는 것이다. 미스율의 0.5퍼센트포인트 차이는 원본이 가까운 메모리인지, 혼잡한 원격 서비스인지에 따라 전혀 다른 비용이 된다.

현실에서 미스가 늘면 원본 서버의 대기열이 길어져 B 자체가 달라질 수 있다. 적중과 미스가 서로 다른 요청 종류에 집중되면 단순 평균도 왜곡된다. 따라서 60μs는 주어진 가정의 경계이지 운영 환경의 자동 선택 기준이 아니다. 10월 12일의 대기행렬 논의처럼 높은 부하에서는 작은 서비스 비용 변화가 대기시간에 더 크게 나타날 수 있다.

10. 2023년 이후 연구를 입장과 보호의 두 결정으로 읽는다

S3-FIFO의 2023년 SOSP 논문은 작은 FIFO 공간에서 새 객체를 먼저 시험하고, 주 저장 공간과 최근 퇴출 이력을 위한 ghost 구조를 함께 사용한다. 핵심은 새로 요청됐다는 이유만으로 오래 머물 자격을 모두 주지 않는다는 것이다. SIEVE와 비교할 때에는 이름보다 “새 객체와 재사용된 객체를 어디에 두는가?”를 보면 차이가 선명해진다. S3-FIFO 원논문

TinyLFU는 또 다른 위치에서 결정한다. 교체 정책이 내보낼 후보를 고른 다음, 최근 빈도의 근사치를 이용해 새 객체를 그 후보 대신 들일 가치가 있는지 판단한다. 입장 정책과 교체 정책을 분리하는 접근이다. 확인한 자료는 2015년 12월 3일 arXiv v2이며, 여기서는 §3의 구조와 §4의 W-TinyLFU를 후속 읽기로 사용한다. TinyLFU v2

이 세 접근을 하나의 사다리처럼 “단순한 것에서 고급인 것으로” 배열하면 중요한 차이를 놓친다. 객체를 들이지 않으면 원본에서 응답은 줄 수 있지만 캐시 공간은 쓰지 않는다. 일단 들인 뒤 빨리 내보내면 짧은 재사용 기회는 주되 보호 기간을 제한한다. 오래 보호하려면 추가 흔적을 기억한다. 각각 실패하는 요청 패턴과 부담하는 메타데이터가 다르다.

ghost는 이름이나 요약 이력을 남기는 것이며 원래 객체의 본문을 그대로 저장하는 공간과 구별된다. 그 이력을 보고 “방금 버렸는데 다시 온 객체”를 알아볼 수 있지만, 이력 자체에도 메모리와 관리비가 든다. 실제 비교에서는 데이터 공간만 같게 맞추고 ghost나 카운터 공간을 무료로 취급하지 않아야 한다.

2023년 S3-FIFO와 2024년 SIEVE가 보여주는 연결점은 교과서의 FIFO·LRU를 폐기한다는 것이 아니다. 자료구조를 자주 고치는 위치, 새 객체가 검증받는 기간, 과거를 기억하는 범위를 재배치하는 것만으로 새로운 설계가 나온다는 것이다. 최신 연구를 이해하는 데 필요한 출발점은 복잡한 이름보다 리스트, 비트, 요청열이다.

11. 좋은 벤치마크는 미스율과 실행 비용을 따로 측정한다

중심 논문은 7개 출처의 1,559개 추적 데이터를 평가하고, 별도 16스레드 시제품 실험에서 최적화 LRU 대비 약 두 배 처리량을 보고했다. 이는 2024년의 해당 실험 조건에 대한 결과다. 모든 캐시가 두 배 빨라진다는 보장은 아니다. 평가 §4

첫 번째 실험은 같은 요청열을 각 정책에 재생하는 정책 시뮬레이션이다. 빈 캐시에서 시작한 구간과 충분히 채워진 구간을 구별하고, 메모리 예산을 맞춰 미스 수와 미스 바이트를 센다. 이 단계는 “무엇을 남겼는가?”에 답한다. 네트워크나 스레드 스케줄링을 생략했다면 처리량까지 결론 내릴 수 없다.

두 번째 실험은 실제 구현의 비용을 측정한다. 같은 해시 테이블, 객체 크기, 할당기, 스레드 수, 용량 분할 조건을 가능한 한 고정하고 CPU 시간과 처리량, p50·p99 지연을 본다. 이 단계는 “남길 대상을 결정하느라 얼마나 일했는가?”에 답한다. 미스율이 낮은 정책이 구현 비용 때문에 CPU를 더 소모할 수 있다.

세 번째는 원본 서버까지 포함한 종단 간 실험이다. 입력 부하를 같게 주었을 때 원본 요청 수, 오류율, 대기시간, 네트워크 사용량을 확인한다. 빠른 캐시 덕분에 더 많은 요청을 받아들이면 원본 부하가 커질 수 있다. 캐시 처리량 하나가 증가했다고 사용자 응답이 같은 비율로 빨라진다고 계산하지 않는다.

객체 크기가 다르면 미스율도 두 가지다. 요청 단위 미스율은 미스 요청 수 ÷ 전체 요청 수이고, 바이트 미스율은 미스로 가져온 바이트 수 ÷ 전체 요청 바이트 수다. 1KB 객체 백 번을 적중시키는 정책과 10MB 객체 한 번을 적중시키는 정책 중 무엇이 더 좋은지는 목표에 달렸다. 평균만 보고 작은 객체와 큰 객체의 효과를 섞지 말자.

실험 보고서에는 초기화 상태, 워밍업 구간, 캐시 예산에 포함한 메타데이터, 객체 크기 분포, 만료 규칙, 부하 생성 방식이 함께 있어야 한다. 알고리즘을 한 줄로 바꿨더라도 이런 조건이 달라졌다면 그것은 정책만의 비교가 아니다. 짧은 반례를 먼저 통과시키고 실제 추적 데이터로 범위를 넓히는 편이 디버깅에도 유리하다.

15

12. 실제 서비스에서는 안전성과 만료를 다시 붙여야 한다

정책의 적중 경로가 리스트를 재배열하지 않는다고 해서 캐시 전체가 자동으로 lock-free가 되는 것은 아니다. 해시 테이블에서 객체를 찾는 동안 다른 스레드가 같은 객체를 삭제할 수 있다. 비트를 만지는 행위와 객체 수명을 안전하게 관리하는 행위도 다르다. 언어의 메모리 모델에 맞는 원자적 접근, 잠금, 참조 보존 같은 장치가 필요할 수 있다.

이 지점이 첫 RCU 글과 연결된다. “어느 객체를 내보낼지” 결정한 뒤에도 누군가가 그 객체를 읽고 있다면 즉시 메모리를 해제해서는 안 된다. 교체 정책은 희생자를 고르고, 수명 관리 기법은 실제로 회수해도 되는 때를 정한다. 둘을 섞어 생각하면 성능 최적화가 use-after-free로 이어질 수 있다.

만료도 별개다. 비트가 1이어도 유효기간이 끝난 응답을 그대로 제공해서는 안 된다. 인가 결과나 자주 변하는 가격처럼 정확성이 중요한 데이터에서는 TTL, 무효화, 버전 확인의 계약이 먼저다. 캐시에서 오래 살아남았다는 사실은 데이터가 계속 참이라는 증거가 아니다.

메타데이터 비용도 구현으로 확인해야 한다. “객체당 한 비트”는 방문 흔적의 크기일 뿐이다. 키, 해시 테이블 엔트리, 리스트 포인터, 정렬을 위한 패딩, 메모리 할당기의 부대비용이 남는다. 특히 작은 객체에서는 본문보다 관리 정보가 더 큰 비중을 차지할 수 있다. 이론적 비트 수만으로 저장 가능한 객체 수를 계산하지 않는다.

적용 후보는 조회가 매우 많고 관리 경합이 실제 병목인 객체 캐시다. 반대로 스캔이 흔하거나 비용이 아주 큰 원본 미스를 줄이는 일이 최우선이면 다른 정책이 더 적합할 수 있다. 정책 교체 전에 실제 요청열에서 두 반례와 비슷한 패턴이 얼마나 나타나는지, 미스 비용과 CPU 비용 중 무엇이 더 비싼지부터 확인하자.

16

13. 오늘의 논증을 하나로 묶기

LRU의 정확한 최근성은 유용한 정보이지만 그 순서를 유지하는 작업도 실행 경로에 들어간다. SIEVE의 실험은 이 정보 전체를 매번 갱신하지 않고도, 제한된 재사용 흔적과 후보 검사 시점으로 충분히 경쟁력 있는 결정을 할 수 있는 경우를 보여준다. 우리가 직접 만든 두 요청열은 같은 규칙이 어떤 상황에서는 이익, 다른 상황에서는 손실을 낸다는 사실을 확인했다.

상각 분석은 비용을 뒤로 미룬 것만으로 총비용이 폭발하지 않는지 따지는 도구였다. V ≤ E + H ≤ R는 비트 초기화의 비용을 이전 적중에 대응시킨 결과다. 반면 개별 요청의 검사 길이는 여전히 커질 수 있으므로 지연시간 문제를 따로 측정해야 한다. 올바른 상한이 무엇에 대한 상한인지까지 말해야 분석이 완성된다.

마지막 비용 모형은 알고리즘 선택을 서비스의 자원 가격과 연결했다. 더 정교한 예측이 지불한 관리비보다 많은 미스 비용을 줄이는가? 간단한 예측으로 아낀 CPU가 추가 미스를 감당할 만큼 가치 있는가? 답은 이름의 유명세보다 요청 패턴과 원본 비용에 달려 있다.

오늘 기억할 문장: 좋은 캐시 정책은 미래를 잘 맞히는 능력과, 그 추측을 유지하는 데 드는 비용을 함께 최적화한다. 다음에 새로운 성능 논문을 읽을 때에는 결과 숫자보다 먼저 관측 정보, 갱신 시점, 버린 정보, 실패하는 요청열을 찾아보자.

Q1. 용량 C = 3인 빈 캐시에 A → B → C → A → D → E → F → A를 보낸다. SIEVE에서 D를 넣은 직후의 리스트와 hand, 최종 적중률을 쓰고, 마지막 A에 대한 LRU의 재사용 거리와 적중 여부를 설명하라. 모든 객체 크기는 같고, 미스 객체는 항상 저장하며 만료는 없다.해설 보기 +

삽입이 오래된 쪽부터 A₀ → C₀ → D₀이고 hand = C다. D 삽입 때 A의 비트를 1에서 0으로 바꾸고 B를 내보냈다. 이어 C와 D를 내보내므로 마지막 A는 남아 있다. SIEVE 적중은 4번째와 8번째의 두 번, 적중률은 2/8 = 25%다. LRU에서 두 A 사이의 서로 다른 객체는 D·E·F로 d(A) = 3이다. 적중 조건 d(A) < C를 만족하지 않아 마지막 A는 미스이며, 전체 적중률은 1/8 = 12.5%다.

Q2. 단일 스레드, 고정 크기 객체, 처음 빈 캐시라는 가정에서 총요청 R = 1,000, 적중 H = 900, 실제 교체 E = 80이다. SIEVE의 총후보 검사 수 V에는 어떤 상한을 줄 수 있는가? 이것이 개별 미스의 최대 검사 횟수도 일정하다는 뜻인지, 용량 C = 100이고 모든 비트가 1인 상태로 설명하라.해설 보기 +

비트 1을 지우는 검사마다 이전의 0→1 적중이 하나 필요하므로 V ≤ E + H = 980이다. 이 값은 총작업량의 상한이다. 개별 미스 때 100개 객체의 비트가 모두 1이면 100개를 지우고 처음 객체를 다시 검사해 내보내므로 101번 검사할 수 있다. 요청당 상각 O(1)과 한 요청의 최악 O(C)는 양립한다. 검사 중 동시 적중이나 객체 크기 차이까지 허용하면 제시한 단일 스레드 상한을 그대로 쓰면 안 된다.

Q3. 정책 L의 요청당 평균 캐시 비용은 0.4μs, 미스율은 5.0%이고, 정책 N은 0.1μs와 5.5%다. 대기시간을 제외하고 미스 추가비용 B가 두 정책에서 같다는 모형 T = c + mB를 사용하자. 손익분기 B와 B = 500μs에서의 두 시간을 구하라. 운영 환경에서 이 계산을 바로 적용하지 못할 이유도 하나 쓰라.해설 보기 +

줄인 비용은 0.3μs, 늘어난 미스 확률은 0.005이므로 손익분기점 B = 0.3/0.005 = 60μs다. 500μs에서는 T_L = 0.4 + 0.050 × 500 = 25.4μs, T_N = 0.1 + 0.055 × 500 = 27.6μs로 L이 유리하다. 실제로는 늘어난 미스가 원본 대기열을 키워 B가 정책별로 달라질 수 있다. 또한 평균 서비스 시간만으로 p99 응답시간이나 객체별 비용 차이를 설명할 수 없다.
