KV cache와 GQA: 왜 Query는 32개인데 Key/Value는 8개만 있어도 되는가

Autoregressive LLM은 이전 토큰의 Key와 Value를 KV cache에 저장해 재계산을 피한다. 그런데 표준 Multi-Head Attention(MHA)은 Query head 수만큼 K/V head도 저장해 긴 문맥에서 메모리와 HBM 대역폭을 크게 쓴다. 그렇다면 왜 Grouped-Query Attention(GQA)은 Query head는 많이 유지하면서 K/V head만 줄여도 품질을 상당 부분 보존할 수 있을까?

02

핵심 질문과 결론

핵심 질문: Autoregressive LLM은 이전 토큰의 Key와 Value를 KV cache에 저장해 재계산을 피한다. 그런데 표준 Multi-Head Attention(MHA)은 Query head 수만큼 K/V head도 저장해 긴 문맥에서 메모리와 HBM 대역폭을 크게 쓴다. 그렇다면 왜 Grouped-Query Attention(GQA)은 Query head는 많이 유지하면서 K/V head만 줄여도 품질을 상당 부분 보존할 수 있을까? 그리고 GQA는 정확히 어떤 비용을 줄이고 어떤 비용은 그대로 남길까?

결론: KV cache는 “계산을 저장공간으로 바꾸는” 전형적인 time-space trade-off다. MHA가 \(H_q\)개의 Query head마다 독립적인 K/V head를 둔다면, GQA는 \(H_q\)개의 Query head를 유지하면서 \(H_{kv}<H_q\)개의 K/V head만 저장하고 여러 Query head가 한 K/V head를 공유한다. 한 sequence의 KV cache 크기는 단순화하면

\boxed{
M_{KV}=2LTH_{kv}d_hs
}

bytes다. 여기서 \(L\)은 layer 수, \(T\)는 cached token 수, \(H_{kv}\)는 KV head 수, \(d_h\)는 head dimension, \(s\)는 원소당 byte 수이며 앞의 2는 Key와 Value 두 개를 뜻한다. 따라서 \(H_{kv}\)를 32에서 8로 줄이면 cache와 해당 cache의 read traffic도 이상적으로 약 1/4로 줄어든다. 하지만 Query head 수 \(H_q\)를 그대로 두므로 \(QK^\top\)와 softmax-\(V\)의 attention 연산량 자체가 1/4로 줄어드는 것은 아니다. GQA의 본질은 “attention 계산을 없애는 기술”보다 decode에서 저장하고 읽어야 할 K/V 표현의 중복을 줄이는 기술에 가깝다.

오늘의 중심 원자료는 Joshua Ainslie, James Lee-Thorp, Michiel de Jong, Yury Zemlyanskiy, Federico Lebrón, Sumit Sanghai의 “GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints”다. EMNLP 2023에 발표됐고, arXiv 최초 공개는 2023-05-22다. 오늘 2026-10-01 KST에 ACL Anthology 공식 PDF의 §1~3, Figure 2, Table 1, Limitations를 실제로 열어 확인했다. 논문은 MHA와 MQA 사이의 중간점으로 GQA를 정의하고, 기존 MHA checkpoint를 적은 추가학습으로 GQA에 전환하는 방법을 제시한다. 03

1. 왜 KV cache가 필요한가

Decoder가 현재 \(t\)번째 token을 생성한다고 하자. 이전 token \(j\)의 hidden state \(x_j\)에서

k_j=x_jW_K,
\qquad
v_j=x_jW_V

를 이미 계산했다. 다음 token을 생성할 때 과거 token의 \(k_j,v_j\)는 바뀌지 않는다. 그러므로 매 step마다 다시 계산하기보다 메모리에 저장해두고 현재 Query만 새로 계산하는 것이 싸다.

즉 KV cache는

\boxed{
\text{재계산 비용 감소}
\leftrightarrow
\text{메모리 사용 증가}
}

라는 교환이다.

Cache가 없으면 같은 과거 token의 K/V projection을 generation step마다 반복 계산한다. Cache가 있으면 각 token의 K/V를 한 번 계산하고 이후에는 읽기만 한다. 긴 generation에서는 계산을 크게 절약하지만 context가 길어질수록 cache가 선형으로 커진다.

이것은 알고리즘에서 익숙한 memoization과 거의 같은 사고다. 계산 결과를 저장해 시간을 아끼지만, 그 대가로 공간을 쓴다.

04

2. MHA 수식 복습

Query head 수를 \(H_q\), 각 head의 dimension을 \(d_h\)라고 하자. MHA에서는 보통 \(H_q\)개의 Q, K, V head가 각각 존재한다.

Q_i=XW_i^Q
K_i=XW_i^K
V_i=XW_i^V

그리고 \(i\)번째 head는

\operatorname{head}_i
=
\operatorname{softmax}
\left(
\frac{Q_iK_i^\top}{\sqrt{d_h}}
\right)
V_i

를 계산한다.

각 head가 서로 다른 Query뿐 아니라 서로 다른 Key와 Value projection까지 갖는다. 표현력은 높지만 decode에서는 과거 모든 token에 대해 \(H_q\)개의 K/V vector를 저장해야 한다.

05

3. MQA와 GQA

Multi-Query Attention(MQA)은 극단적으로 모든 Query head가 단 하나의 K/V head를 공유한다.

H_{kv}=1.

GQA는 그 중간이다. Query head 수 \(H_q\)를 유지하면서 K/V head 수 \(H_{kv}\)만 줄인다. \(H_q\)가 \(H_{kv}\)로 나누어떨어진다고 하고

r=\frac{H_q}{H_{kv}}

를 group size라 하자.

Query head \(i\)가 사용하는 KV head를

g(i)=
\left\lfloor
\frac{i}{r}
\right\rfloor

라고 하면

\operatorname{head}_i
=
\operatorname{softmax}
\left(
\frac{Q_iK_{g(i)}^\top}
{\sqrt{d_h}}
\right)
V_{g(i)}

가 된다.

따라서

H_{kv}=H_q

이면 MHA,

H_{kv}=1

이면 MQA,

1<H_{kv}<H_q

이면 GQA다. 중심 논문도 GQA-\(G\)에서 \(G\)개의 query group이 각각 한 K/V head를 공유하는 구조로 정의하고, \(G=1\)을 MQA, \(G=H\)를 MHA로 설명한다. ACL 앤솔로지

06

4. 왜 Query는 많아도 K/V는 공유할 수 있을까

직관적으로 Query는 “현재 token이 과거 문맥에 던지는 질문”, K/V는 “과거 문맥을 검색하기 위한 인덱스와 내용”에 가깝다.

MHA는 질문마다 과거 문맥을 별도의 K/V 표현으로 저장한다. MQA는 모든 질문이 동일한 K/V 표현을 사용한다. GQA는 비슷한 질문 몇 개가 하나의 K/V 표현을 공유한다.

여러 Query subspace가 완전히 독립적인 K/V 표현을 요구하지 않는다면 중복된 K/V head를 합쳐도 상당한 표현력을 유지할 수 있다. 하지만 너무 많이 합치면 정보 병목이 생긴다. 이것이 MHA의 품질과 MQA의 효율 사이에서 GQA가 중간점을 찾는 이유다.

정보이론적으로 보면 \(H_{kv}\)는 단순한 hardware knob이 아니라 context representation의 채널 수라고 생각할 수 있다. 채널이 너무 많으면 중복을 저장하고, 너무 적으면 서로 달라야 할 표현까지 강제로 합친다.

07

5. KV cache 크기 공식

Batch size까지 포함하면 단순화한 KV cache 크기는

\boxed{
M_{KV}
=
2BLTH_{kv}d_hs
}

다.

여기서 \(B\)는 동시에 처리하는 sequence 수, \(L\)은 Transformer layer 수, \(T\)는 현재 context 길이, \(H_{kv}\)는 KV head 수, \(d_h\)는 head당 dimension, \(s\)는 한 원소의 byte 수다.

이 식은 모든 layer가 같은 head 구조이고 KV quantization, sliding-window attention, prefix sharing, allocator/paging overhead 등이 없다는 교육용 근사다.

08

손계산

다음과 같이 두자.

L=32,
\quad
H_q=32,
\quad
d_h=128,
T=32768,
\quad
s=2\text{ bytes},
\quad
B=1.

BF16 또는 FP16이라고 생각하면 된다.

MHA에서는

H_{kv}=32

이므로

M_{KV}
=
2\times32\times32768\times32\times128\times2

bytes이고,

\boxed{
M_{KV}=16\text{ GiB}
}

다.

GQA-8에서는

H_{kv}=8

이므로

\boxed{
M_{KV}=4\text{ GiB}
}

다.

MQA에서는

H_{kv}=1

이므로

\boxed{
M_{KV}=0.5\text{ GiB}
}

다.

같은 32K context에서

\boxed{
16\text{ GiB}
\rightarrow
4\text{ GiB}
\rightarrow
0.5\text{ GiB}
}

로 줄어든다.

Batch가 16이면 GQA-8의 KV cache만 단순 계산으로 약

4\times16=64\text{ GiB}

가 된다. 여기에 model weights, temporary workspace, allocator 여유공간은 아직 포함하지 않았다.

그래서 대규모 serving에서는 모델 weight보다 KV cache가 동시 사용자 수를 제한하는 상황도 충분히 생길 수 있다.

09

6. 메모리뿐 아니라 대역폭 문제다

Decode step마다 새 Query는 과거 \(T\)개의 Key와 Value를 읽어야 한다. 따라서 한 step의 KV read traffic도 대략

O(LTH_{kv}d_h)

에 비례한다.

9월에 다룬 Roofline 관점으로 보면 autoregressive decode는 작은 batch에서 연산기보다 HBM에서 weight와 KV를 가져오는 속도가 병목이 되기 쉽다. GQA는 arithmetic 자체보다 한 token을 생성하기 위해 이동해야 하는 byte 수를 줄이는 방향의 최적화다.

중심 논문도 autoregressive decoder inference의 병목을 decoder weight와 K/V를 반복 로드하는 memory-bandwidth overhead로 설명하고, MQA/GQA가 K/V head 수를 줄여 이 부담을 완화한다고 설명한다. ACL 앤솔로지

10

7. 중요한 오해: GQA가 attention FLOPs까지 같은 비율로 줄이는 것은 아니다

Query head 수 \(H_q\)가 그대로라면 각 Query head는 여전히 과거 \(T\)개 위치와 dot product를 계산해야 한다.

따라서 대략적인 attention score 계산은

O(LTH_qd_h)

에 비례한다.

반면 KV cache memory는

O(LTH_{kv}d_h)

에 비례한다.

즉

\boxed{
H_{kv}\downarrow
\Rightarrow
\text{cache memory와 K/V bandwidth}\downarrow
}

이지만,

\boxed{
H_q\text{ 고정}
\Rightarrow
\text{attention score FLOPs는 상당 부분 유지}
}

된다.

2025년 “Cost-Optimal Grouped-Query Attention for Long-Context Modeling”은 이 구분을 더 명확하게 수식화한다. 해당 논문은 per-token inference cost를 대략

C_{\text{infer}}(T)
\approx
2N+4TLd_hn_h
M_{\text{infer}}(T)
\approx
N+2TLd_hn_{kv}

로 나눈다. \(N\)은 model parameter 수, \(n_h\)는 attention/query head 수, \(n_{kv}\)는 KV head 수다. 즉 context-dependent compute는 \(n_h\), context-dependent memory는 \(n_{kv}\)에 직접 좌우된다. ACL 앤솔로지

이 구분이 매우 중요하다.

GQA는 주로 memory/bandwidth knob이고, Query head 수는 attention compute knob에 더 가깝다.

11

8. 중심 논문의 실제 주장과 근거

Ainslie et al.은 기존 MHA checkpoint를 GQA/MQA로 바꾸는 uptraining 절차를 제안했다.

같은 group에 속한 기존 K/V projection matrix들을 mean pooling해 새 K/V head를 초기화하고, 원래 pretraining의 약 5%를 추가 학습한다. 논문에서 \(5\%\) uptraining의 T5-XXL 실험은 약 600 TPUv3 chip-days를 사용했다. ACL 앤솔로지

논문의 Table 1에서 T5-XXL 계열 inference time은

\text{MHA-XXL}=1.51
\text{MQA-XXL}=0.24
\text{GQA-8-XXL}=0.28

로 보고됐다.

여러 summarization·translation·QA dev metric의 논문 내 평균은 각각

47.2,\quad46.6,\quad47.1

이었다. 저자들의 해석은 GQA가 MQA에 가까운 속도로 MHA에 가까운 품질을 얻었다는 것이다. ACL 앤솔로지

다만 이 수치는 T5.1.1 encoder-decoder, TPUv4 timing, greedy decoding, 특정 task와 input/output 길이에서 나온 결과다. 모든 decoder-only LLM, GPU, batch size, context length에 그대로 적용되는 universal speedup이 아니다. 논문 스스로도 decoder-only model에서 직접 비교하지 않았다는 점과 long-sequence quality 평가의 어려움을 Limitations에 적고 있다. ACL 앤솔로지

9. 왜 mean pooling으로 시작할까

MHA checkpoint를 GQA로 바꾸면 여러 K/V head를 하나로 합쳐야 한다.

논문은 같은 group의 K/V projection을 평균내는 방식이 첫 head 하나만 고르거나 random initialization하는 것보다 실험상 좋았다고 보고한다. ACL 앤솔로지

선형대수적으로 보면 기존 head들의 정보를 완전히 버리지 않고 group의 중심에 가까운 projection에서 시작하는 것이다.

하지만 평균은 서로 다른 전문화 방향을 희석할 수 있다. 그래서 conversion 직후 끝내는 것이 아니라 추가 uptraining으로 새 sharing structure에 적응시킨다.

이 과정은 모델 압축에서 자주 보는

\boxed{
\text{구조 축소}
\rightarrow
\text{정보 손실}
\rightarrow
\text{재학습으로 재적응}
}

패턴이다.

11. 2025년 흐름: 같은 GQA가 모든 context에 최적인가

2025년 EMNLP의 Cost-Optimal GQA 연구는 context length를 고정하지 않고 inference resource allocation 문제로 본다.

Context가 짧으면 model weights 같은 time-invariant 비용의 비중이 크다. Context가 길어질수록 attention computation과 KV cache처럼 \(T\)에 비례하는 time-variant 비용이 커진다. 따라서 4K serving에 좋은 \(n_h,n_{kv}\) 조합이 128K에도 최적이라는 보장은 없다.

저자들은 최대 1.2B parameter 규모의 실험과 scaling analysis에서 128K 조건에서는 attention head를 줄이고 일부 자원을 model size 쪽에 재배분하는 configuration이 더 비용효율적일 수 있다고 보고했다. 또한 자신들의 recipe로 선택한 configuration이 Llama-3식 GQA 구성과 비교해 memory와 FLOPs를 50% 이상 줄이면서 목표 loss를 유지했다고 보고한다. ACL 앤솔로지

중요한 한계도 있다. 이 결과는 최대 1.2B 규모의 empirical validation과 scaling assumptions에 기반한 것이다. 이를 “Llama 3 405B 전체를 다시 학습해 직접 50% 절감했다”는 뜻으로 읽으면 안 된다. ACL 앤솔로지

12. 2026년 최신 방향: GQA도 아직 cache를 너무 많이 저장하는가

2026-09-08 공개된 preprint “Grouped Value Attention: Efficient KV Caching via On-Demand Key Reconstruction”는 한 단계 더 간다.

GQA도 매 token마다 Key와 Value를 모두 저장한다는 점을 문제로 보고, grouped Value는 저장하되 content Key는 learned linear map으로 재구성하는 방식을 제안한다.

저자들은 연구한 configuration에서 matched GQA 대비 persistent cache scalar를 약 45~47% 줄였다고 보고한다. 350M-parameter model을 30B FineWeb-Edu token으로 학습한 조건에서 16-dimensional positional variant의 5-task 평균 accuracy는 44.18, GQA는 44.36이었다고 보고한다. 다만 초록 기준으로 end-to-end decoding kernel 성능은 아직 평가 중이라고 밝힌다. arXiv

Grouped Value Attention — arXiv

여기서 시스템 성능의 중요한 원칙이 나온다.

\boxed{
\text{cache가 작아졌다}
\neq
\text{latency가 같은 비율로 빨라졌다}
}

재구성 compute, kernel fusion, GPU occupancy, tensor-parallel communication까지 합쳐야 최종 wall-clock이 결정된다.

13. GQA와 다른 최적화는 무엇이 다른가

FlashAttention은 attention matrix를 HBM에 크게 materialize하지 않도록 tiling해 I/O를 줄이는 exact attention algorithm/kernel 계열이다.

GQA는 애초에 저장하는 K/V head 수를 줄이는 architecture-level 변경이다.

PagedAttention은 KV cache를 page 단위로 관리해 fragmentation과 serving memory management를 개선한다.

Speculative decoding은 작은 model의 proposal을 target model이 묶어 검증해 target의 serial decode step 수를 줄인다.

이들은 상당 부분 직교적이다. 실제 serving stack에서는

\boxed{
\text{GQA}
+
\text{efficient attention kernel}
+
\text{paged KV memory}
+
\text{speculative decoding}
}

이 함께 쓰일 수 있다.

시스템에서는 한 가지 최적화가 모든 병목을 해결하는 경우가 드물다.

17

14. 반대 관점과 한계

GQA에도 분명한 비용이 있다. K/V head sharing은 정보용량을 줄이기 때문에 MQA가 GQA보다 cache는 더 작더라도 품질 손실이 커질 수 있다. 이미 MHA로 pretrain된 model이라면 GQA 전환은 단순한 config 변경이 아니라 projection structure를 바꾸고 재학습해야 하는 일이다.

또 GQA는 긴 context의 근본적인 quadratic prefill attention을 없애지 않는다. KV memory는 \(T\)에 선형이지만 full prefill attention score 계산은 여전히 \(T^2\) 성격을 가진다.

그리고 inference bottleneck은 hardware와 workload에 따라 달라진다. Small-batch decode에서는 bandwidth 절감의 가치가 크지만, 큰 batch나 다른 accelerator에서는 compute, interconnect, scheduler가 더 중요할 수 있다.

마지막으로 cache를 줄였다고 자동으로 더 많은 사용자를 안정적으로 받을 수 있는 것도 아니다. Weight memory, temporary workspace, fragmentation, prefix-cache policy, latency SLO를 함께 봐야 한다.

18

15. 시스템 렌즈: KV cache는 memoization이다

운영체제나 알고리즘 관점에서 KV cache는 memoization과 같다.

과거 token의 K/V는 다시 계산할 수 있지만 비싸므로 결과를 저장한다.

따라서

\text{compute를 아끼려면 memory를 쓴다.}

그리고 memory가 비싸지면

\text{저장된 표현을 압축하거나 공유한다.}

GQA는 memoized state 중 head별 중복을 제거하는 방식이라고 볼 수 있다.

19

16. 데이터베이스 렌즈: Query는 많아도 index 복사본이 Query마다 필요하지 않다

서로 다른 SQL query가 같은 index를 공유한다고 생각해보자.

Query마다 완전히 별도의 index 복사본을 유지하면 표현의 자유도는 높지만 저장비와 cache traffic이 커진다.

GQA는 여러 Query head가 한 KV representation을 공유한다는 점에서

\boxed{
\text{여러 질의가 공통 index를 사용하는 구조}
}

와 비슷하다.

하지만 모든 workload를 하나의 index로 몰면 특정 query가 느려지듯, 모든 Query head를 단 하나의 KV head에 묶는 MQA는 표현력 손실을 만들 수 있다.

20

17. 경제학 렌즈: 희소자원 하나가 아니라 포트폴리오를 최적화한다

LLM serving의 희소자원은 FLOPs 하나가 아니다.

HBM capacity, HBM bandwidth, compute, interconnect bandwidth, latency budget이 동시에 제약이다.

GQA는 특히 HBM capacity와 bandwidth를 절약하는 대신 representational capacity 일부를 포기한다.

따라서 목표는

\boxed{
\min \text{ serving cost}
\quad
\text{s.t. quality}\ge q^\*
}

에 가깝다.

“KV head를 최대한 줄인다”가 목적이 아니다.

좋은 architecture는 품질 제약을 만족하는 범위 안에서 가장 비싼 자원을 아끼는 구조다.

21

18. 정보이론 렌즈: 병목의 폭을 어디에 둘 것인가

MHA는 각 Query head가 독립적인 K/V channel을 갖는다.

MQA는 모든 Query가 하나의 shared channel을 통과한다.

GQA는 몇 개의 channel만 남긴다.

그래서 \(H_{kv}\)는 단순 hardware parameter이면서 information bottleneck의 폭이기도 하다.

너무 넓으면 memory를 낭비할 수 있고, 너무 좁으면 서로 달라야 할 contextual representation이 강제로 합쳐진다.

좋은 설계는

\boxed{
\text{중복정보는 공유하고 중요한 다양성은 보존한다}
}

는 문제다.

22

19. 의사결정 렌즈: 평균이 아니라 병목자원을 최적화하라

Model parameter 수가 작다고 serving이 반드시 싼 것은 아니다.

Long context에서는 작은 model도 KV cache와 attention 때문에 비쌀 수 있다.

반대로 약간 더 큰 model이라도 KV head와 attention-head 구조를 잘 설계하면 특정 long-context workload에서 전체 inference 비용이 낮아질 수 있다.

따라서 시스템 선택에서

\boxed{
\text{“몇 B model인가?”}
}

하나만 보는 것은 기업을 PER 하나로만 보는 것과 비슷하다.

실제 병목자원과 사용패턴을 봐야 한다.

23

오늘 기억할 한 문장

\boxed{
\text{GQA는 Query를 줄이는 기술이 아니라 여러 Query가 과거 문맥의 Key/Value 기억을 공유하게 만드는 기술이다.}
}

핵심 수식은

\boxed{
M_{KV}\propto TLH_{kv}d_h
}

이고,

\boxed{
\text{attention score compute}
\propto TLH_qd_h
}

라는 차이다.

그래서 긴 context에서 중요한 질문은 단순히 “모델이 몇 B인가?”가 아니라,

\boxed{
\text{한 token을 생성할 때 무엇을 얼마나 저장하고,
HBM에서 얼마나 읽으며,
얼마를 계산하는가?}
}

이다.

잠깐, 내 언어로 설명해 보기

Q1. 40-layer model에서 \(H_q=40\), \(H_{kv}=8\), \(d_h=128\), context \(T=16{,}384\), BF16 2 bytes, batch \(B=1\)이라고 하자. 위의 단순식으로 KV cache를 계산하고 같은 \(H_q=40\)의 MHA와 비교해 몇 배 줄어드는지 구하라.해설 보기 +

문제 1에서

M_{KV}
=
2\times1\times40\times16384\times8\times128\times2

이므로

2{,}684{,}354{,}560\text{ bytes}
=
\boxed{2.5\text{ GiB}}

다.

MHA는 \(H_{kv}=40\)이므로

2.5\times\frac{40}{8}
=
\boxed{12.5\text{ GiB}}.

따라서 이 단순모형에서 GQA는 MHA의 \(1/5\), 즉 5배 작은 KV cache를 사용한다.

Q2. \(H_q=32\), \(H_{kv}=8\)인 GQA에서 group size \(r\)과 Query head 0, 7, 8, 15, 31이 사용하는 KV head 번호를 구하라. 0-based indexing을 사용한다.해설 보기 +

문제 2에서

r=\frac{32}{8}=4

이고

g(i)=\lfloor i/4\rfloor.

따라서

g(0)=0,
\quad
g(7)=1,
\quad
g(8)=2,
g(15)=3,
\quad
g(31)=7.
Q3. 어떤 연구자가 “\(H_{kv}\)를 32에서 8로 줄였으니 attention FLOPs도 정확히 4분의 1이다”라고 주장했다. 왜 틀릴 수 있는가? KV cache, attention score compute, K/V projection을 분리해 설명하라.해설 보기 +

문제 3에서 KV cache와 그 read traffic은 \(H_{kv}\)에 비례하므로 32에서 8로 줄이면 약 1/4이 될 수 있다. K/V projection parameter와 해당 projection 연산도 줄어든다.

하지만 Query head가 32개 그대로라면 각 Query head가 \(T\)개의 과거 위치와 score를 계산하므로 주요 \(QK^\top\) 및 softmax-\(V\) attention compute는 \(H_q\)에 비례해 상당 부분 그대로다.

따라서

\boxed{
\text{memory 절감률}
\neq
\text{전체 attention FLOPs 절감률}
}

이다.
